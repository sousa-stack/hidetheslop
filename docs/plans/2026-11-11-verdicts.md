# Verdict downloads

Roadmap step 5, item 19. Written 2026-11-11. The first verdict was published that day, from five real installs, so there's a real list to build against. The design and promises are in `docs/CROWD-API.md`, and this doesn't change the API. If it seems to need a change, stop and ask.

Nobody commits, pushes or deploys until Kevin says so. It's version 1.9.0, because people will see pictures hidden by the crowd.

## What it does

The extension downloads the list of pictures the crowd has confirmed as AI, keeps it on your computer, and hides any picture whose hash matches, with a bar saying the crowd flagged it. Matching happens on your computer. Nothing is looked up per picture, and that must never change, because a lookup would hand the server a stream of what you look at.

## The setting

- **`useCrowdList`, default on, in `storage.sync` like the other hiding switches.** Downloading the list sends nothing about you or what you browse: everyone asks for the same pages of the same list, Cloudflare serves most of them, and the server sees an IP address in transit, as it does for the model download. It isn't sharing, so it doesn't sit behind `shareRatings`. Kevin decides the default. The recommendation is on, because it's the payoff for everyone who shares and it collects nothing.
- A switch in Settings, in Pictures, after Share your ratings: **Hide pictures the crowd flagged**, with a line on what it downloads and that matching happens on your computer.
- It needs your robot on, because matching needs the picture downloaded and hashed, and only the robot does that today. Roadmap item 22 covers people without the robot, and isn't part of this. Say so beside the switch when the robot is off.

## Downloading the list

- `GET https://api.hidetheslop.com/v1/verdicts?since=<seq>&hashVersion=1`, with `credentials: 'omit'`, `referrerPolicy: 'no-referrer'`, no custom headers and a timeout. Follow `more` until it's false, then keep the returned `seq`.
- Apply `add` and `remove` to a local set, `crowdList` in `storage.local`, with `crowdSeq`. Validate every hash against `^[0-9a-f]{16}$`, and ignore the reply if it doesn't parse.
- When: on start if the list is older than 6 hours, then every 6 hours on the existing alarm pattern (`alarms`, top-level listener, created if missing). The server's job runs hourly and the list is cached an hour, so more often gains nothing.
- **Jitter:** a random delay of up to 30 minutes before each scheduled fetch, so installs don't all ask at the same minute.
- Fail quietly. A dead server means the old list stays.
- On Firefox, the Origin strip rule must cover these GETs too (it's POST-only now), or don't fetch. Check what a GET sends, the same way `eval/vote-check.mjs` checked POSTs.
- Turning the setting off stops fetching and deletes `crowdList` and `crowdSeq`.

## Matching

- A picture gets hashed only when the setting is on and the list isn't empty, and only for pictures your robot already inspects, reusing that same download. Use the `SlopVision.hash` path from voting, or hash inside `inspect()` from the same blob, whichever keeps it to one download. Measure the added time and memory per picture, in Chrome and Firefox (`about:processes`, not Activity Monitor).
- Within 3 bits counts as a match, the same limit the server merges at. Index the list by the four 16-bit bands, as the server does, so a check is a few lookups, not a scan.
- `check()` returns `crowd: true` alongside `meta` and `score`. The content script hides with the reason "the crowd flagged it", whatever your robot's score and cutoff.
- **Your own rating wins.** If you rated that picture Not AI, it isn't hidden, and the bar's Show and Not AI work as they do today.

## The bar

- "Hide the Slop · the crowd flagged it", with the same Show button, and the same red ✕ AI, hide it and green ✓ Not AI after it. Answering counts as an ordinary rating, and is shared only if `shareRatings` is on.

## Changes after review (these override anything above)

A review on 2026-11-11 found these problems. Where this section and the parts above disagree, this section wins.

**Only fetch when it can be used.** Fetch only when `useCrowdList` is on, `visualCheck` is on and the model is downloaded, because matching needs the robot and `visualCheck` defaults to off. Turning off any of those deletes `crowdList`, `crowdSeq` and `crowdFetchedAt`. Do this in a background `storage.onChanged` listener and again at startup, as `votes.js`'s `tidy()` does.

**Alarms, not timers.**
- A `setTimeout` dies when the worker or background page idles.
- Create a `fetch-crowd` alarm with `delayInMinutes` set to a random 1 to 30 and `periodInMinutes: 360`, with its own top-level listener. `send-votes` is separate.
- Persist `crowdFetchedAt`. Fetch from the alarm, and from `onStartup` only when stale. Never fetch from top-level code, because Chrome wakes the worker on every `check` message, and a fetch there would follow your browsing.

**A full resync every 7 days.** Expiry or a restore can leave the client set wrong with no `remove` to fix it. So every 7 days, fetch from `since=0` and replace the set rather than merging, which is also the URL that caches best.
- Apply a fetch only after every page validates.
- Write `crowdList` and `crowdSeq` in one `storage.local.set`.
- Stop if `more` is true but `seq` didn't move, and cap the number of pages.

**Your own verdicts.** A rating is stored by URL key, with no hash, and the oldest drop after 500. So keep a separate `ownVerdicts` list of `{key, phash, label}`, about 2,000 at most, filled at every rating whether or not sharing is on. A picture you rated Not AI is never crowd-hidden, matched by key or within 3 bits. "Forget them" clears it, along with your ratings.

**Hashing.**
- `inspect()` returns `phash` from the blob it already holds, after `toTensor`, whenever the crowd list is in use. That's one download, and pictures inspected before the first list arrives still get a hash. Don't change `toTensor`'s input, because that would move the model's scores.
- `queueVote` reuses `inspected.phash` rather than fetching again.
- Skip `data:` URLs.
- Hash one picture at a time, behind a lock, and skip anything over 12 megapixels. Two at once can reach about 320 MB on Firefox's background page, outside the model's worker.
- Measure time and memory in Chrome and Firefox with `about:processes`.

**Storage.**
- `storage.local` holds 10 MB, and ratings already use several. Cap `crowdList` at 20,000 hashes, and catch quota errors on the crowd write alone, so a full store can't make `learn()` lose a rating.
- Keep the index as four Maps, built when first needed. `check()` awaits loading it, so the first checks after a worker wakes don't miss.

**Firefox.** Add `"get"` to `origin-rules.json`. Write `listAllowed()`, needing host access and the `strip-origin` ruleset only, because `allowed()` also needs sharing and the data permission. Add `redirect: 'error'`. Check the headers a real Firefox GET sends, as `TESTING.md` describes for POSTs.

**Pictures outside a post.** A crowd hide on a lone picture or video blurs it. Since 5221d48, resting the mouse on it shows a **Show** button, which is enough, and the plan relies on it.

**Telling people.** Existing 1.8.0 users get the list and the new hiding on update, so say so in `CHANGELOG.md`, the privacy policy and the Settings copy.

**Build details.** Add any new file to `importScripts` in `background.js` and to Firefox's `background.scripts` in `build.mjs`.

**Known gap, not built here:** a forged verdict hides a picture for everyone. The aggregate job recomputes `published` every hour, so today the only way to pull one is deleting its votes by hand, which needs Kevin's OK. Record it in `CROWD-API.md`, and put a proper block list on the roadmap before launch.
